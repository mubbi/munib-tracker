# Store listing assets

Generated and reference files for **App Store Connect**, **Google Play Console**, and in-repo publishing docs.

Full pipeline guide: [`docs/STORE_ASSETS.md`](../../../docs/STORE_ASSETS.md).

## Directory layout

```
store-assets/
├── captures-native/          # Full native matrix (Maestro / watch + TV simctl/adb) — optional to commit
│   ├── android/<locale>/<theme>/<scene>.png
│   ├── ios/<locale>/<theme>/<scene>.png
│   ├── watch/en/<scene>.png
│   ├── tvos/<locale>/<theme>/<scene>.png
│   └── android-tv/<locale>/<theme>/<scene>.png
├── captures/                 # Studio inputs — **per platform** (do not share)
│   ├── android/<locale>/<theme>/
│   └── ios/<locale>/<theme>/
├── ios/screenshots/          # Final App Store PNGs (incl. watch-ultra-3/, apple-tv-1080p/)
├── android/screenshots/      # Final Play Store PNGs (incl. android-tv-1080p/)
└── android/feature-graphic/  # Play feature graphic 1024×500
```

**Regenerate:**

```bash
pnpm screenshots:android              # or screenshots:ios — native phone captures
pnpm screenshots:watch                # Apple Watch Ultra 3 (macOS)
pnpm seed:screenshot-studio           # refresh deck copy
pnpm sync:screenshot-captures         # copy captures into editor
pnpm dev:screenshot-studio            # export each device tab in UI
pnpm distribute:screenshot-exports    # copy exports here
```

See also `tools/screenshot-studio/README.md`.

## Raw app captures (inputs to the studio)

Eight images per **platform** × locale × theme before exporting marketing frames:

```
captures/android/<locale>/{light,dark}/
captures/ios/<locale>/{light,dark}/
  home.jpg
  tracker.jpg
  qaza.jpg
  zikr.jpg
  quran.jpg
  qibla.jpg
  names-of-allah.jpg
  tasbeeh.jpg
```

iOS and Android captures stay separate so one platform never overwrites the other. Screenshot Studio marketing decks use **light** captures by default (`studioTheme` in `packages/store-screenshots/spec.json`, override with `STUDIO_THEME=dark`). iPhone/iPad decks read `captures/ios/…/light/`; Android decks read `captures/android/…/light/`.

**Automated:** `pnpm screenshots:android` or `pnpm screenshots:ios` seeds demo data via Maestro, captures all screens, and copies marketing aliases (light and dark) into `captures/<platform>/<locale>/<theme>/` (see `apps/app/scripts/screenshots/lib/config.mjs` → `STUDIO_ALIASES`).

**Manual:** run the app on iOS Simulator or Android emulator at native resolution in the studio theme (light by default); switch locale before each batch. JPEG or PNG accepted.

## Native capture archive

`captures-native/` holds the full matrix: every documented screen × locale (all 24 `AppLocale`s by default, `LOCALES=…` to narrow) × `light`/`dark` × platform. Useful for QA, design review, and picking alternate marketing crops. Generated by [`apps/app/scripts/screenshots/`](../scripts/screenshots/README.md).

## Shared spec package

Device sizes, locale list, capture filenames, and slide scene names are centralized in `@munib-tracker/store-screenshots` (`packages/store-screenshots/spec.json`, which the scripts read).
