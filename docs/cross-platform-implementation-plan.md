# Cross-platform implementation plan

Status: approved for execution (Phase 4) — live status in [`cross-platform-progress.md`](./cross-platform-progress.md)

Dependency-aware roadmap for taking the redesign to every surface: Web, iOS / iPad, Android phone / tablet, Apple TV / Android TV, Apple Watch, Wear OS, widgets and Live Activities. The shared language is [`design-system.md`](./design-system.md); token flow is [`cross-platform-design-system.md`](./cross-platform-design-system.md); per-platform requirements and QA checklists are [`platform-ux-guidelines.md`](./platform-ux-guidelines.md). React Native tasks (`P<phase>-nn`) are defined in [`ui-ux-implementation-plan.md`](./ui-ux-implementation-plan.md) and only referenced here; native tasks (`N-nn`) are defined here. Finding IDs (`E-nn` …) are from [`ui-ux-audit.md`](./ui-ux-audit.md); platform detail is in [`cross-platform-ui-ux-audit.md`](./cross-platform-ui-ux-audit.md) and [`platform-feature-matrix.md`](./platform-feature-matrix.md).

**Owner decisions that shape this plan:** D-UX1 amber / lime light shades darkened (flows to every native surface through codegen) · D-UX3 tablets keep the custom side rail · D-UX4 build a Wear OS Compose tasbeeh counter · D-UX5 finance tools hidden on TV by default.

## Working-tree note (read before starting a native lane)

Audit E was written against the committed tree. The working tree on 2026-11-25 is ahead of it in two places, so every native task below is **verify first, then finish** — the acceptance criteria are behavioural and do not assume which state you find.

The counter exists **as Views, not Compose** — see `N-24` |
| Apple Watch | One `List` + one tasbeeh view, `@State` only                                                   | `WatchNowView`, `WatchTodayView`, `WatchOverviewView`, vertical-page `TabView`, `@AppStorage` tasbeeh store                                                                                                                                                                                       | E-32 / E-34 are partly addressed; `N-31`–`N-33` verify and close the remainder                                                     |

### Wear OS tasbeeh counter — UX spec

One screen, one job. Brand colour and copy are shared with the app; layout, type and components are Wear Material 3.

| Topic             | Spec                                                                                                                                                                                                                                                                                                                       |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Entry points      | Launcher → watch app home → **Tasbeeh**; Tasbeeh tile "Open" (`N-25`)                                                                                                                                                                                                                                                      |
| Layout            | Full-screen, round-safe (`ScreenScaffold`, content inset ≥ 5% from the edge). Centre: count in the largest Wear M3 display numeral; below it "of 33" (or "∞") in a label style; progress arc around the bezel edge filling toward the target. Sequence mode: the step's short name above the count and "Step 2 of 3" below |
| Counting          | Tap anywhere on the counter surface = +1. Rotary (crown / bezel) clockwise = +1 per detent threshold; anticlockwise does nothing. No swipe gestures besides system swipe-to-dismiss                                                                                                                                        |
| Secondary actions | One 48dp button at the bottom centre ("Options", does not count) opens an options screen (`ScalingLazyColumn`, rotary scrolls here): **Undo last** · **Target** 33 / 99 / 100 / ∞ · **Mode** Free / After-Salah sequence (only when the phone sent steps) · **Reset** (confirm dialog, two actions)                        |
| Feedback          | Light haptic per count; distinct stronger pattern on reaching the target; in sequence mode a different short pattern on auto-advance. Arc and numeral change to the success colour at the target with a check glyph — never colour alone                                                                                   |
| Target reached    | Free mode: stays at the target count with "Start again" (confirmed) replacing the Options hint; further taps keep counting only in ∞ mode. Sequence: advances by itself; after the last step shows "All done" and "Start again"                                                                                            |
| Persistence       | Count, target, mode, sequence position and date in the existing `WearTasbeehStore` (shared with the tile). Survives process death, wrist-down and reboot. Watch-local: nothing is written to the phone (no business-logic change)                                                                                          |
| Ambient / battery | No keep-screen-on. On resume the count is unchanged. No animation while ambient                                                                                                                                                                                                                                            |
| Colour            | Dark surface only; accent, success and text from `WearTokens.generated.kt`                                                                                                                                                                                                                                                 |
| Text              | Wear M3 typography constants; strings in `values*/strings.xml` (en / ar / ur now, 24 after `N-28`). Step names are the short labels the phone already sends — no Qur'an, hadith or dua text on the watch                                                                                                                   |
| Accessibility     | Counter surface: content description "Tasbeeh counter, 12 of 33", click action label "Count one"; target reached and step changes announced (polite live region); Options and every row ≥ 48dp; respects system font scale within the round-safe area                                                                      |
| Out of scope      | Custom zikr text entry, syncing counts to the phone, voice counting, scripture text                                                                                                                                                                                                                                        |

### How to verify the counter

Android prebuild + Wear OS emulators (small round and large round), then a physical watch for feel.

- [ ] `./gradlew :wear:testDebugUnitTest` — reducer tests: count, undo at 0, target reached, ∞ mode, sequence auto-advance, reset, date rollover.
- [ ] `:wear:assembleDebug` from a clean `pnpm cleanbuild:app:android`; phone app build is unaffected.
- [ ] Small round emulator: nothing clipped at default and largest font scale; Options button fully inside the round-safe area.
- [ ] Tap 33 times: haptic each time, stronger pattern and success state at 33.
- [ ] Rotary (emulator rotary input): clockwise counts one per detent, anticlockwise does nothing; on the Options screen rotary scrolls instead.
- [ ] Force-stop and relaunch: count, target and mode are unchanged. Reboot the emulator: unchanged.
- [ ] Count in the app, swipe to the tile: tile shows the same count (`N-25`).
- [ ] Sequence mode with steps sent from the phone: advances 33 → 33 → 34 and ends on "All done".
- [ ] Reset asks for confirmation; Undo does not.
- [ ] TalkBack: surface announced as "Tasbeeh counter, N of M"; double-tap counts; target reached is announced.
- [ ] `ar` and `ur`: strings localised, layout mirrored where applicable, numerals readable.
- [ ] Device: 5 minutes of counting — no dropped taps, haptics keep up, battery drop noted in the tracker.
