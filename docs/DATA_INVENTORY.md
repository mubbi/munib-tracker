# Data inventory

Where every piece of user data lives, whether it syncs or is backed up, what clears it, and how it is protected. Reviewed 2026-11-24 (owner request #10).

Keep this file current when you add storage. The checks that enforce most of it:

| Guard                                                                                                                                                   | What it checks                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `apps/app/src/sync/sync-entities-parity.test.ts`                                                                                                        | Client entities (`TYPED_SYNC_ENTITIES` + `BLOB_ENTITIES`) match the API `SYNC_ENTITIES` and the generated `SyncRecordDtoEntity`. ## How data is cleared

| Action                         | Where                                                                    | Effect                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Reset settings to defaults** | Settings › Data & storage (`lib/settings/reset.ts`)                      | Resets registered settings only. Logs, notes, vault, progress and caches are kept.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Reset app data**             | Settings › Data & storage (`components/settings/editors/reset-rows.tsx`) | Signed in: `POST /auth/reset-app-data` turns every `sync_records` row into a tombstone, writes a `data_reset` marker (other devices wipe on their next pull), deletes `user_media` and the server inbox. Then on this device: `wipeLocalDeviceData()`, PIN factory reset, inbox clear. The account, sessions, push tokens and circles are kept.                                                                                                                                                                                                                                                            |
| **Delete account**             | Profile (`app/profile/index.tsx`)                                        | `DELETE /auth/account` (see "Account deletion" below), then the same local wipe as Reset app data, then a new guest session.                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Sign out**                   | Profile (`providers/auth-provider.tsx` `invalidateAuthSession`)          | Unregisters this device's push token (`DELETE /notifications/push-token`, by device id, while the session is still valid), deletes the surface-push registration, unsubscribes Web Push, revokes the session (`POST /auth/logout`), clears the session from SecureStore, drops the account's server inbox rows, and starts a guest session. **Local tracking data stays on the device** (offline-first: it carries over to the guest and to the next sign-in). Sync cursors are reset on the next sign-in to a different account (`readMetaFor` in `sync/sync-engine.ts`). D47: sign-out keeps local data. |
| **`data_reset` pulled**        | `sync/sync-engine.ts`                                                    | Another device reset the account, so this device runs `wipeLocalDeviceData()`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Vault "Start fresh"**        | `resetVaultOnDevice()` (`lib/vault/vault.ts`)                            | Deletes vault documents, keyring, sync state, the DEK and the sealed files on this device. The server is not touched.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

`wipeLocalDeviceData()` (`lib/wipe-local-data.ts`) runs `resetDatabase()` (every `RESET_KEYS` tree: base key, `/…` shards and the `__corrupt` quarantine copy). It also clears: downloaded audio and QCF fonts, recitation and pronunciation models, the morphology file and root index, search history, the in-app inbox, PIN storage, the widget snapshot, the theme mirror, the vault DEK and sealed vault files, the child session (token and meta), native focus-lock data (`reset()`: iOS App Group plan, selection and state with monitoring stopped and the shield cleared; Android prefs cleared and alarms cancelled), printable exports, the native widget / Siri / Wear command queue (drained and discarded), and the web OCR consent flag plus Tesseract's cached language data (IndexedDB `keyval-store`). It also ends the vault unlock grace window. Then `reloadAllStores()` reloads every live store from disk.

## 1. Local keys (`DB_KEYS`, AsyncStorage)

Prefix `@munib-tracker/db/`. On native, AsyncStorage is the app sandbox (SQLite on Android, files on iOS). On web it is `localStorage`.

**Classes:**

- **U** = `userData`: backed up and wiped on reset.
- **W** = `watermark`: backed up and wiped.
- **C** = `cache`: wiped, never backed up.
- **D** = `deviceLocal`: wiped, never backed up.
- **S** = `schema`: survives reset.

"Sync" names the cloud entity.

## 3. Cloud sync

- **Transport:** HTTPS only. Bearer JWT (HS256, pinned) on native. HttpOnly cookies on web.
- **Pushes:** guests never sync (the server returns 403). Pushes are delta-filtered and LWW on `updatedAt`, capped at 500 records per push.
- **Entities:** 12 typed (`TYPED_SYNC_ENTITIES`) + 48 blob (`BLOB_ENTITIES`, including the 7 vault entities) = 60 client entities (63 on the server). The server's `SYNC_ENTITIES` also has three server-only names:
  - `data_reset`: the reset marker, never pushed.
  - `reading_text_visibility`: deprecated (D13).
  - `khushu_journal`: retired (D46). It is accepted but never stored; the client sends one empty tombstone to clear the old copy.
- **D46 private data:** the excused period and the khushu journal sync only through `vault_excused` / `vault_khushu`; with vault sync off they stay on the device.
  - The sync engine reconciles the mirrors before the push and after the pull (`reconcilePrivateMirrors`).
  - The server strips `activeExcusedReason`, per-log `excusedReason` and exact coordinates on push **and** on pull. Migration `1720000013000-StripPrivateSyncPlaintext` removes them from existing rows and deletes the `khushu_journal` rows.
  - Each account's first sync after the update re-pushes its preferences and excused logs with the same `updatedAt`, so the stored copy loses the plaintext (`SyncMetadata.privacyCleanup`).
- **Validation:** vault payloads must be a `VaultEnvelope` or keyring and ≤ 256 KB (`isValidVaultPayload`). `quran_notes` is shape-checked and ≤ 1 MB.
- **Account switch:** cursors are tagged with `accountId`. Signing in to a different account drops the pull cursor, push watermark, blob fingerprints, parked blob merges and the parked vault inbox, so the next sync is a full push + pull reconciled by LWW (fixed 2026-11-24).

**Logging:** API loggers record failure classes and counts only. Values, sync payloads, cells and IPs are never logged; the account id is logged on a failed blob purge only. The global `SafeExceptionFilter` (`common/safe-exception.filter.ts`) logs an unhandled error as class + method + route template + status only (no URL, body, IP or driver message) and answers with a generic 500. Auth rate limits key Redis or in-memory buckets on `ip:<addr>`, with a short TTL. Those are not logs.

**Client Sentry:** tags only, never user content (`captureAppException` with `area` and key-name tags). Child sessions send crash data only: no user, request, breadcrumbs or transactions.
