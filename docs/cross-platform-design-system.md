# Cross-platform design system

Status: implemented (Waves 1–6, 2026-11-25) — the source of truth for UI work; per-task status and any deviations in [`ui-ux-progress.md`](./ui-ux-progress.md), reviews in [`ui-ux-final-review.md`](./ui-ux-final-review.md). Native/device verification still pending where marked.

How one design language reaches every Munib Tracker surface: the Expo app (iOS, Android, Web, Apple TV / Android TV) and the native companions (watchOS app, complications, iOS widgets, Live Activities, focus shield, App Intents, Android widgets, Wear OS tiles). Tokens and components are in [`design-system.md`](./design-system.md); per-platform requirements and QA are in [`platform-ux-guidelines.md`](./platform-ux-guidelines.md). Finding IDs (`A-nn`, `E-nn`, `F-nn`) refer to the Phase 1–2 audits.

## Three layers

| Layer                    | What it holds                                                                                                                                                      | Owner                                                                                                                                                  | Changes when…            |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------ |
| **1. Global language**   | Brand (deep green, cream, gold), 12 accents, surface ladder, status hues, contrast rules, voice and glossary, motion personality, "scripture is never compromised" | [`packages/theme`](../packages/theme/src/) + [`design-system.md`](./design-system.md)                                                                  | The brand changes (rare) |
| **2. Platform systems**  | Navigation model, type scale, targets, focus, back, sheets, haptics — whatever the host OS defines                                                                 | [`platform-ux-guidelines.md`](./platform-ux-guidelines.md); in code: `Platform` / `isTV()` / `TV_DENSITY` branches, SwiftUI and Wear Material defaults | An OS guideline changes  |
| **3. Shared components** | The primitives in `apps/app/src/components/ui/` — one API, platform-specific behaviour inside                                                                      | [`design-system.md` § Components](./design-system.md#components)                                                                                       | A product need changes   |

Rule of precedence: layer 1 fixes **what it looks and sounds like**, layer 2 fixes **how it behaves**, layer 3 hides the difference from screens. A screen never branches on platform for something a primitive should own.

Native companions (Swift, Kotlin) take layer 1 **colour only**. They use their host's type scale, spacing and components (SwiftUI text styles, Wear Material 3) — a widget should look like a well-made widget in brand colours, not like a shrunken app screen.

## Token layering

The usual primitives → semantic → component → platform stack, mapped onto the packages that already exist. No new package, no token-build dependency.

| Tier                                | Lives in                                                                                                                                                                                          | Examples                                                                                           | Consumed by                                                                             |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **Primitive**                       | `packages/theme/src/accents.ts`, `resolve-theme.ts` (`lightBase` / `darkBase`); `apps/app/src/constants/theme.ts` (`StatusPalette`, `Brand`, `Mushaf`, `CategoryHues`, `Metal`)                   | `#F5F0E6`, forest `#2E7D32` / `#66BB6A`, `#D9604C`                                                 | Semantic tier only — never screens                                                      |
| **Semantic colour**                 | `packages/theme` `ThemeColors` (`resolveTheme()`), then `apps/app/src/lib/theme-tokens.ts` `ThemeTokens` (`computeThemeTokens()`)                                                                 | `background`, `accentText`, `accentOnSoft`, `status.danger.fill`, `focusRing`, `inputSurfaceError` | RN via `useThemeTokens()`; web CSS variables; native via snapshot + generated constants |
| **Semantic layout / type / motion** | `apps/app/src/constants/theme.ts` (`Spacing`, `Radius`, `Control`, `IconSize`, `BorderWidth`, `ZIndex`, `Opacity`, `Breakpoints`, `Shadows`), `constants/motion.ts`, `components/themed-text.tsx` | `Spacing.three`, `Control.md`, `Springs.press`, `type="button"`                                    | RN only                                                                                 |
| **Component**                       | Inside each primitive in `components/ui/` — **not exported as tokens**                                                                                                                            | Button md = `Control.md` + `Radius.md` + `button` type                                             | The primitive itself                                                                    |
| **Platform delta**                  | `tvDp()` / `TV_DENSITY`, `TvLayout`, `TvType`, `Platform.select`, `isTV()`                                                                                                                        | `Control.minTouch` 44 vs 48; `TvLayout.minFocusTarget`                                             | Semantic tier and primitives                                                            |

There are deliberately **no per-component tokens** (`buttonPrimaryBg`, …). If two primitives need the same value it becomes a semantic token; otherwise it stays a line inside the component.

### Never double-scale (TV)

Authoring unit is Android-TV dp. `TV_DENSITY` is 2 on tvOS, 1 elsewhere ([`TV.md` § Density](./TV.md#density--type-apple-tv-vs-android-tv)).

| Value                                                                                                          | Already scaled?                    | In a TV branch write |
| -------------------------------------------------------------------------------------------------------------- | ---------------------------------- | -------------------- |
| `Spacing.*`, `Radius.*`, `Control.*` (except `minTouch`), `BorderWidth.thin/thick`, `TvLayout.*` layout tokens | yes                                | the token as-is      |
| `ThemedText` sizes (variant, `TvType`, inline `fontSize` / `lineHeight`)                                       | yes, inside `ThemedText`           | raw dp               |
| `SymbolView size` / `IconSize.*`                                                                               | yes, by the `expo-symbols` TV shim | raw dp               |
| `IconButton hitTarget`, `TvLayout.minFocusTargetDp`, `TvLayout.bodyFontSize` / `titleFontSize`                 | scaled by the consumer             | raw dp               |
| Any other literal (`width: 44`, `TextInput` font size, image/SVG size)                                         | **no**                             | `tvDp(44)`           |

### Web CSS variables

One variable set, published by `MunibThemeProvider` on web whenever the theme changes (today `web-keyboard-shortcuts.tsx:26` sets `--munib-focus` to raw `accent`, and `styles/focus-visible.css` has a second, never-themed `--focus-ring-color: #1f7a63` — E-03, A-05, F-60).

| Variable                   | Value                                    | Used by                                                                   |
| -------------------------- | ---------------------------------------- | ------------------------------------------------------------------------- |
| `--munib-focus`            | `tokens.focusRing`                       | The single `:focus-visible` rule in `app/+html.tsx`                       |
| `--munib-focus-halo`       | `colors.background`                      | 2px halo between element and ring (two-tone ring, visible on any surface) |
| `--munib-bg`, `--munib-fg` | `colors.background`, `colors.foreground` | Pre-hydration paint, scrollbars                                           |

A region on a non-ladder surface (the deep-green hero) overrides `--munib-focus` locally to `Brand.heroAccent`. Delete `styles/focus-visible.css` and its import in `app/_layout.tsx` after moving its `forced-colors` block into `+html.tsx`; drop the global `border-radius: 4px`.

## Sync and codegen (colour only)

**Why a generator is justified (E-44, E-45, E-46, audit E §4):** the same palette is hand-copied in at least five places and has already drifted — default green is `#059669` in 17 native/plugin literals vs `#2E7D32` in the app; secondary text is `#4A5F56` in `androidCard.tsx` / gallery XML vs `#4A6157` in tokens and Swift; watch screenshot scenes use a third palette; `$widgetBackground` has no dark value. The palette is small (10 surface colours × 2 schemes, 12 accents × 2, 4 status hues) and the repo already runs Node generators (`build:data`, `generate:brand-assets`, `sync-pwa-manifest.mjs`).

**Why colour only:** type and spacing on native surfaces should follow the host system (SwiftUI text styles, Wear Material). Exporting them would fight the platform.

| Step | File                                                                              | Content                                                                                                                                                                                     |
| ---- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | `packages/theme/src/native-tokens.ts` (new, pure)                                 | `{ light, dark, defaultAccent: { light, dark }, status, danger: { fill, onFill } }` built by **calling `resolveTheme()`** — no second copy of any hex                                       |
| 2    | `apps/app/scripts/generate-native-tokens.mjs` (new, plain Node string templates)  | Writes the four outputs below                                                                                                                                                               |
| 3    | `apps/app/targets/_shared/MunibTokens.generated.swift`                            | `enum MunibTokens { static let lightCard = Color(red:…) … }` — `WidgetPalette`, watch app, Live Activity fallback read it                                                                   |
| 4    | `apps/app/src/lib/appSurfaces/widgets/widgetTokens.generated.ts`                  | Replaces the `LIGHT` / `DARK` literals in `widgetTokens.ts`                                                                                                                                 |
| 5    | `apps/app/plugins/generated/native-tokens.json`                                   | `require`d by `withWearOs.cjs`, `withAndroidWidgetGallery.cjs`, `homeScreenSurfaces.cjs` and the `targets/*/expo-target.config.js` files (`$accent`, `$widgetBackground` with light + dark) |
| 6    | Drift test in the existing suite (Jest in `apps/app`, alongside the plugin tests) | Regenerates in memory and fails if a committed generated file differs — same idea as the OpenAPI drift check in `check:ci`. **No new CI job**                                               |
| 7    | Replace the 17 `#059669` literals                                                 | With the generated default accent (forest)                                                                                                                                                  |

Generated files are committed (Swift targets and config plugins are read at prebuild, before any build step runs) and carry a "generated — do not edit" header. Command: `pnpm --filter app generate:native-tokens` (script name to be added).

Runtime theming does not change: the app keeps writing resolved colours into the snapshot, so the user's accent and forced light/dark reach every companion without native code knowing the palette. Generated constants cover only (a) before the first snapshot, (b) follow-system appearance, (c) build-time assets.

Contrast on native surfaces follows the same targets: snapshot `primary` is a **fill / tint**; text on widget cards uses `textPrimary` / `textSecondary`; add `primaryText` (= `accentText`) to the snapshot if a companion needs accent-coloured text.

## Feature scope by surface

From the audit E suitability matrix — design work should not try to bring every feature everywhere.

| Surface                 | Role                                                           | In scope                                                                                  | Out of scope                                                                        |
| ----------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Phone (iOS / Android)   | Complete product                                               | Everything                                                                                | —                                                                                   |
| Web                     | Complete product; best for long reading and forms              | Everything except device-only features                                                    | Focus lock, widgets                                                                 |
| Tablet                  | Phone feature set, list–detail layouts                         | Everything                                                                                | —                                                                                   |
| TV                      | Shared, lean-back: times, recitation, reading, family progress | Salah marking (simplified), times, Qur'an text + audio, Learn, stats (read-only)          | Private data (vault, debts, wasiyyah), finance tools by default, typing-heavy flows |
| Watch / Wear            | Glance + one action                                            | Next Salah, mark current Salah (explicit button, undo), tasbeeh count, streak/Qaza number | Any scripture, reading, settings, lists longer than a screen                        |
| Widgets / Live Activity | Glance                                                         | Next Salah, countdown, today's progress, one or two actions                               | Navigation, configuration UI                                                        |

## Governance

| Change                                 | Do                                                                                                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| New or changed colour                  | Edit `packages/theme` (or `StatusPalette` / `theme-tokens.ts`) → add the pair to the contrast tests → run the native-token generator → update [`design-system.md`](./design-system.md) |
| New layout / type / motion token       | Add to `constants/` with `tvDp` where it is a layout size → document with its evidence                                                                                                 |
| New primitive                          | Only when ≥ 3 feature copies exist or a platform requirement cannot be met otherwise; add to the catalogue                                                                             |
| Platform-specific behaviour            | Inside the primitive (`Platform` / `isTV()`), documented in the table above — not in screens                                                                                           |
| Native surface (Swift / Kotlin) colour | Never a literal; snapshot value or generated constant                                                                                                                                  |
| tvOS visual change                     | Needs a Mac pass — see the QA checklist in [`platform-ux-guidelines.md`](./platform-ux-guidelines.md#tv)                                                                               |
