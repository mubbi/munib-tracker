# Proof log: Salah focus lock (NF-3.13, D4 / D17)

- **Feature:** an opt-in block of the apps the user chooses during a short window around each Salah, until they mark the Salah prayed or the window ends; gentle / firm / strict unlock modes and a limited number of emergency unlocks.
- **Code:** `apps/app/src/lib/focus-lock/*`, `apps/app/src/components/focus-lock/*` (evidence card: `focus-lock-evidence.tsx`), routes `apps/app/src/app/focus-lock/*`, native `apps/app/modules/munib-focus-lock/` + `apps/app/targets/munib-tracker-focus-*`. Copy: `apps/app/scripts/i18n/focus-lock-i18n.json` (`focusLock.*`).
- **Review:** AI proof-backed review (D11), 2026-11-23 (logged 2026-11-24). Scripture is cited by reference only: the evidence lines paraphrase the meaning in one short clause and deep-link the ayah in the bundled reader; no ayah text is typed in code or i18n.

Against the bundled corpus the app renders: `apps/app/assets/data/quran/arabic/<sss>.json` (Uthmani text) and `apps/app/assets/data/quran/translation/en-pickthall/<sss>.json` (Pickthall), read by index on 2026-11-24. Numbering is standard Hafs (Kufan) ayah numbering, the same as the reader.

## 3. Removed / not asserted

- No hadith is cited (plan §12 lists only the three Qur'an refs). No reward or virtue claim about blocking apps is made.
- The window length / modes are product choices, not religious rulings; copy never calls them sunnah.

## 4. Privacy (plan §2.4)

- App selections never leave the device: iOS `FamilyActivitySelection` tokens in the App Group, Android package names in SharedPreferences (`docs/FOCUS_LOCK_FILINGS.md` §3). Emergency unlocks are logged locally (`DB_KEYS.focusLockDevice`, deviceLocal) and shown only as a neutral count.
- Lock-screen text is generic: "Tap to confirm your Salah" / "Salah focus on".
- Synced: only `UserPreferences.focusLock` (which prayers, timing, mode).
